# flowertalker

Личный сайт-сад: история одного дня от рассвета до ночи, рассказанная скроллом. Гости только смотрят и открывают — ничего не пишут и не загружают. Весь текст на странице правит владелец через скрытую панель садовника.

## Что на странице

1. **Как растёт** — первый экран и четыре главы. Справа закреплён цветок: при прокрутке он прорастает из семени (корни → стебель → листья → цветок), часы в шапке идут с 05:40 до 21:30.
2. **Садовник** — фото, короткий рассказ, факты, раскрывающиеся kin-list и психологический портрет.
3. **Что цветёт** — четыре грядки-увлечения. На широких экранах лента едет вбок при вертикальном скролле, на телефонах листается пальцем. «Открыть» показывает окно с подробностями (у музыки — плеер с треками).
4. **Гербарий** — листки с мыслями, переворачиваются по нажатию.
5. **Вечер в саду** — ночная сцена: луна поднимается, появляются звёзды и светлячки.

Учитываются `prefers-reduced-motion` (цветок сразу распущен, без закрепления и параллакса) и светлая/тёмная тема системы, плюс ручной переключатель.

## Панель садовника

Вход не виден в композиции страницы:

- маленькая звёздочка ✳ рядом с копирайтом в подвале;
- сочетание **Ctrl + Alt + G**;
- адрес с `#sadovnik` в конце.

Код панели (`admin.js`, `admin.css`) загружается только после этого — гости его не скачивают. После ввода `ADMIN_PASSWORD` сервер выдаёт временный ключ на 12 часов (хранится в `sessionStorage` вкладки; сам пароль больше никуда не отправляется).

Что умеет:

- **Править текст** — включает правку прямо на странице: любой текст становится редактируемым, изменённые места подсвечиваются. `Ctrl + E` — вкл/выкл, `Ctrl + S` — сохранить, `Esc` — выйти из поля.
- **Панель → Тексты** — все ~100 текстовых полей сайта по разделам, с поиском, фильтром «только изменённые», кнопками «показать на странице» и «вернуть исходный». Пустое поле скрывает элемент (например, лишнюю строку kin-list).
- **Ссылки и фото** — ссылка на Steam, адреса и описания фотографий с предпросмотром.
- **Музыка** — загрузка MP3 (до 15 МБ) и удаление треков; применяется сразу.
- **Резерв** — скачать копию текстов в JSON, загрузить её обратно, вернуть все исходные тексты.
- Счётчик несохранённых правок, «Отменить», предупреждение при закрытии вкладки с несохранёнными правками, сворачивание панели в маленькое семечко.

Сохраняются только отличия от исходного текста в `index.html` — так правки в коде продолжают доходить до сайта. Сохранённый текст сервер встраивает прямо в страницу, поэтому гости сразу видят актуальную версию без мигания.

## Локальный запуск

Требуется Node.js 20+.

```powershell
Copy-Item .env.example .env
# замените ADMIN_PASSWORD в .env на длинный случайный секрет
node --env-file=.env server.mjs
```

Тесты:

```powershell
npm test
```

## Деплой в Railway

1. Создайте проект Railway и подключите GitHub-репозиторий.
2. Railway автоматически использует `railway.toml` и команду `npm start`.
3. В **Variables** добавьте `ADMIN_PASSWORD` — длинный уникальный секрет. Не добавляйте его в Git.
4. Добавьте **Volume**, смонтированный в `/app/data`. `content.json`, `music.json` и загруженные MP3 создаются в нём автоматически.
5. После деплоя откройте выданный Railway-домен и проверьте `/`.

`PORT` Railway задаёт автоматически. Один Volume должен обслуживаться одним экземпляром приложения: JSON-хранилище сериализует записи только внутри одного процесса. Ключи входа живут в памяти процесса — после перезапуска нужно войти снова.

Старый файл `data/stickers.json` (гостевые записки) больше не используется; его можно удалить с тома.

## API

- `GET /api/content` — сохранённые тексты, ссылки и фото.
- `POST /api/admin/login` — `{ "password": "..." }` → `{ "token": "..." }`; 8 неудачных попыток за 15 минут блокируют вход с адреса.
- `GET /api/admin/session`, `POST /api/admin/logout` — проверка и завершение сессии.
- `PUT /api/admin/content` — сохранить `{ texts, links, images }`; требует `Authorization: Bearer <token>`. Ссылки — только `https:`, `http:`, `mailto:` или `#якорь`; картинки — только `https:`.
- `GET /api/music`, `GET /api/music/:id` — список треков и воспроизведение.
- `POST /api/admin/music` (тело `audio/mpeg`), `DELETE /api/music/:id` — требуют Bearer-токен.

Страница отдаётся с Content-Security-Policy (`script-src 'self'`), текст выводится только через `textContent`. Не логируйте заголовок `Authorization` и не передавайте токен в URL.
